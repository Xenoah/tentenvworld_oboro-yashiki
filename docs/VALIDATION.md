## 試験方法の区別

- マルチプレイ実試験は公式の**LocalTransport / BroadcastChannel**、同じブラウザコンテキスト内の別タブ。**WebRTCや別端末の通信試験ではない**。
- 4人認識・同時取得・ホスト移譲を実試験後、ソフトウェアGPUの負荷を減らすため他の2タブを閉じ、移動区画を1タブで検証。その後2タブを再入場させて勝利/敗北/再開始を共有した。全区画を常時4画面描画しながら走破したとはしていない。
- 開始は画面上のボタン、移動は実キーボード入力。長い移動区間を省くため、試験コードは公式のdebug engine経由でテレポートを使う。仕掛けは登録された本物のClickable callbackを呼び、実際のホスト宛イベントと距離検証を通す。全クリックを画面のピクセル座標で操作した試験ではない。
- 時間切れは時計のfixture、捕縛は敵と参加者の配置fixtureから通常のhost tickを動かして確認。勝敗stateを直接書いて成功扱いしていない。
- 標準能力互換試験は同梱クライアントからoptional APIを取り除いたもの。**未改変の別の公式クライアントでの通し試験は未実施**。
- 本番ビルド試験は `.ttvw` の内容を `scripts/serve.mjs` で展開配信し、公式クライアントの `devWorld` ローダーで読んだ。公式SDKのアーカイブ検証は別途通過しているが、親サーバーの「制作」画面で実登録した試験ではない。[拡張の適用方法と統合範囲](CLIENT_EXTENSION.md) を参照。

## 性能の実測と限界

4タブ時の一標本は約111 draw calls / 320,970 triangles / 96 textures / JS heap 219 MB（1タブ）。低画質・renderScale 0.5のSwiftShaderでFPSの丸め表示は0〜2となり、ソフトウェア描画では快適に遊べる速度ではなかった。GPU機の性能やQuestのフレームレートに換算できない。

静的建築は素材単位で結合、影付きライトは一つ、水面はシンプルな透明マテリアル、テクスチャは768px、敵の位置は5Hz以下のsnapshot。4人の標準VRMも描画される。VR実機では画質/影/アバター負荷の追加チューニングが必要になりうる。

## 実試験から修正した問題

1. indexed/non-indexed建築geometry混在による読み込み失敗を統一処理で修正。
2. 開発用通信の初回hello片方向未完了に、discovery/link再送を追加。既存認証条件は変更しない。
3. 画像読み込み中の初期落下に、Suspense外の玄関安全床と入場時teleportを追加。
4. 水中から別区画へのワープが古い移動範囲に戻される問題を、移動リースの行先適合確認で修正。回帰テストあり。
5. ジャンプ台が高台の下面に衝突する軌道を、上向き射出＋前進入力に変更。実着地まで確認。
6. 壁/天井の快適モードで視点が天井の外へ出る問題を、目の位置だけ表面法線方向へずらして修正。
